# Execution Manager

تطبيق مستقل لإدارة الحسابات المالية لمشروعات تنفيذ التشطيبات. لا يعتمد على WeeklyPlanner ولا يتصل ببياناته أو Firebase الخاص به.

## الوظائف الأساسية
- إدارة عدة مشروعات والتبديل بينها.
- لوحة ملخص للتحصيلات والربح المحجوز ومصروفات التنفيذ والمتاح المخصص للتنفيذ.
- تسجيل تحصيلات العميل مع حفظ نسبة الربح وقت تسجيل كل دفعة.
- إدارة بنود التنفيذ: الكمية والوحدة وطريقة الحساب والحالة.
- اتفاق مستقل للمونة والخامات واتفاق مستقل للأجرة داخل كل بند.
- إسناد المونة/المورد والأجرة/المقاول بشكل منفصل.
- حسابات مستقلة للمقاولين والصنايعية وكشف حساب لكل منهم.
- تسجيل دفعات المونة والأجرة وربط كل دفعة بالبند والمقاول المختار.
- فصل فاتورة شراء المورد عن سدادها: الفاتورة تسجل التكلفة والالتزام، والسداد يسجل حركة نقدية مرتبطة بالفاتورة ولا يكرر التكلفة.
- تسجيل الأجور المستحقة والمعتمدة بشكل مستقل عن دفعات الأجرة والسُلف.
- تدوين يومية الموقع: التنفيذ والكميات والوحدات والطاقم والتوريدات والملاحظات والمعوقات، دون إدخالها في الحسابات المالية.
- تعديل سجلات الفواتير والأجور والتدوينات والتحصيلات والمصروفات بدل حذفها وإعادة إدخالها.
- تسجيل المصروفات المباشرة وربطها ببند عند الحاجة.
- نسخ احتياطي JSON واستيراد النسخ الحالية والقديمة.

## المرحلة الثانية — تسجيل يومي وتقارير ذكية مساعدة
- شاشة موحدة لتسجيل المصروفات والمشتريات ودفعات الأجرة والتحصيلات.
- كتابة الحركة باللغة الطبيعية؛ يساعد التحليل في التقاط المبلغ ونوع الحركة، مع مراجعة المستخدم للبند والشخص والمبلغ قبل الحفظ.
- إدخال صوتي بالعربية المصرية عبر Web Speech API عند دعم المتصفح.
- قراءة صور الفواتير مبدئيًا باستخدام Tesseract.js (عربي + إنجليزي)، واستخراج النص لمراجعته قبل التسجيل. يتطلب اتصال إنترنت لتحميل محرك OCR وملفات اللغة عند أول استخدام.
- اقتراح البنود والأشخاص المسجلين باستخدام الاسم أو الأسماء البديلة، مع تأكيد صريح قبل إنشاء سجل جديد.
- البحث داخل قوائم بنود التنفيذ والمقاولين والصنايعية، بالإضافة إلى البحث في تفاصيل الحركات.
- تعديل الأسماء البديلة للبنود والأشخاص من صفحات السجلات.
- تقارير حسب بند التنفيذ والشخص/المورد وإجمالي المشروع، مع بحث وفلاتر تاريخ ومقارنة بالفترة السابقة المماثلة، وطباعة التقرير.
- إجابات حسابية محلية محدودة للأسئلة الشائعة عن بند أو شخص أو التحصيلات أو المصروفات. هذه الإجابات مبنية على قواعد وبيانات السجلات وليست محادثة ذكاء اصطناعي مفتوحة.
- تنبيهات مساعدة للحركات المتطابقة المحتملة والمصروفات غير المصنفة.
- النسخة الاحتياطية الجديدة تتضمن إصدار المخطط وتاريخ التصدير، مع استمرار دعم ملفات النسخ القديمة.

## قواعد الحساب
- فواتير المشتريات تُحتسب تكلفة مرة واحدة. دفعات المورد المرتبطة بالفاتورة تُحتسب كتدفق نقدي وتخصم من المتبقي على الفاتورة، ولا تُضاف مرة ثانية إلى التكلفة.
- الأجرة المعتمدة تُحتسب تكلفة مستحقة. السلفة ودفعة الصنايعي تُحتسبان كتدفق نقدي، ولا تتحولان إلى أجرة مكتسبة إلا عند تسجيل واعتماد الأجرة.
- المتاح بعد الربح المحجوز يعتمد على التحصيلات ناقص المدفوعات والمصروفات النقدية المسجلة، وليس على قيمة الفواتير غير المسددة.
- يومية الموقع سجل تشغيلي مستقل ولا تدخل في إجماليات الماليات.
- المدفوع للمقاول يسجل كحركة دفع واحدة في سجل الدفعات ويظهر في حساب البند وحساب المقاول.
- المصروف المباشر يسجل في سجل المصروفات ولا يكرر كدفعة مقاول.
- مصروفات التنفيذ في لوحة التحكم = المصروفات المباشرة + دفعات المقاولين.
- الربح المحجوز لكل تحصيل = قيمة التحصيل × نسبة الربح المحفوظة وقت التسجيل.
- المتاح المخصص للتنفيذ = إجمالي التحصيل − الربح المحجوز − مصروفات التنفيذ.
- هذا المؤشر ليس رصيد الخزنة النقدي الفعلي.

## يومية الموقع
- التدوينات لا تحمل قيمة مالية؛ تسجل التاريخ والبند والكمية والوحدة والطاقم ونوع الحدث والتفاصيل.
- يمكن تعديل أو حذف التدوينة دون تغيير الحسابات المالية.

## التخزين والمزامنة والخصوصية
- يحتفظ التطبيق بنسخة محلية في LocalStorage باستخدام المفتاح الحالي `execution-manager-v02`؛ لم يتم تغيير المفتاح أو حذف بيانات سابقة.
- المزامنة السحابية اختيارية وتبدأ بعد تسجيل الدخول بحساب Google من قسم «المزامنة السحابية» في الإعدادات.
- تُحفظ مساحة كل مستخدم في Firestore تحت `users/{uid}/workspaces/main`، ولا يمكن لحساب قراءة مساحة حساب آخر عند تطبيق قواعد الأمان أدناه.
- عند أول ربط، إذا كانت هناك بيانات محلية وسحابية معاً، يطلب التطبيق موافقة صريحة لدمج السجلات غير المتكررة. عند تطابق معرّف سجل، تكون نسخة السحابة هي المعتمدة.
- التعديلات الواردة من الجهاز الآخر تُطبّق فوراً عندما لا توجد تعديلات محلية معلقة. عند تعارض متزامن تتوقف الكتابة تلقائياً ويطلب التطبيق اختيار نسخة السحابة أو رفع نسخة هذا الجهاز؛ لا يستبدل النسختين بصمت.
- تسجيل الخروج لا يحذف البيانات المحلية أو السحابية. استخدم التصدير الاحتياطي قبل تغيير الجهاز أو مسح بيانات المتصفح.
- الاستيراد المحلي يستبدل بيانات التطبيق الحالية بعد تأكيد المستخدم؛ يُنصح بتصدير نسخة حالية أولاً.
- يحتفظ التطبيق بنسخة بيانات واحدة داخل مستند Firestore مع حد أمان 900 KiB. إذا اقترب حجم البيانات من هذا الحد، يلزم نقل التخزين إلى مستندات متعددة قبل متابعة المزامنة.

## حدود يجب معرفتها
- تحليل النص والصوت وOCR أدوات مساعدة فقط؛ راجع الحقول المستخرجة يدويًا قبل التسجيل.
- دقة OCR تتأثر بجودة الصورة والخط والإضاءة، وقد يحتاج تحميل محرك OCR وملفات اللغة إلى اتصال إنترنت.
- دعم الصوت يختلف حسب المتصفح والجهاز.
- طبقة Firebase مستقلة عن محرك الحسابات؛ لا تغيّر معادلات التكلفة أو الربح أو أرصدة البنود. السجلات الجديدة (فواتير المشتريات، الأجور المعتمدة، ويومية الموقع) تدخل ضمن كائن الحالة نفسه وتُزامن مع بقية البيانات.

## التشغيل
افتح `index.html` أو استخدم رابط GitHub Pages بعد نشر التغييرات.

## إعداد Firebase
1. أنشئ Cloud Firestore في وضع Production وفعّل Google ضمن Authentication.
2. أضف `abdos6335-netizen.github.io` إلى Authentication → Settings → Authorized domains.
3. انشر قواعد Firestore التالية من تبويب Rules:

```javascript
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /users/{userId}/workspaces/{workspaceId} {
      allow read, write: if request.auth != null
                         && request.auth.uid == userId;
    }
  }
}
```

4. افتح التطبيق ثم الإعدادات → المزامنة السحابية → الدخول باستخدام Google.
5. احتفظ بنسخة JSON احتياطية قبل أول ربط. لا تفتح قواعد Firestore للعامة.

ملاحظة: مفاتيح Firebase Web SDK المضمنة في الواجهة تُستخدم لتعريف تطبيق الويب؛ الحماية الفعلية تعتمد على Authentication وقواعد Firestore أعلاه.
